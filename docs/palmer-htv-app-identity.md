# Palmer's named HTV application identity — review-only

**Not a live access grant.** This PR replaces the former Hack Hours-only per-person activation idea. It adds no service-grant database, no admin-activation endpoint, no session minting and no global auth bypass. Palmer is a **named HTV user** whose effective permissions come from the existing `roles` table on *every request*. A separately owner-provisioned Cloudflare Access service token authenticates that named identity only on a dedicated Access-protected API hostname; the Worker verifies the provider signature, issuer, audience, client ID and exact hostname before mapping the assertion to the configured existing user. A service cannot change its own binding or grant/revoke its own role.

## Existing capability map

- **Highest HTV application role: active global `super_admin` (`scope_type=global`, `scope_id=*`).** It inherits all `admin` and organizer API access across events and can grant/revoke `admin` and (with this PR, through the existing audited role API) `super_admin`. It is *not* Cloudflare account/root access. The owner must explicitly approve this unusually broad application role and its 15-seat social-vault implication before granting it. `admin` is broad app administration but cannot grant/revoke `admin` or `super_admin`; `organizer/global` works events and sponsorships but lacks admin/vault access; `organizer/event/hack-hours` is event-only.
- Active global admins/super-admins have **implicit social-vault read and management**, including credential reveal, subject to the existing vault encryption key, audited requests and the 15-effective-seat cap. Explicit `social_vault_members` owner/member grants are separately managed; `member` is reveal-only. App role revocation stops implicit vault access unless an explicit membership remains. Passwords already copied cannot be revoked; rotate exposed provider passwords if needed.
- App RBAC does **not** provide Cloudflare account/root privileges, Cloudflare Access token/policy administration, raw D1 access, CI/deploy credentials, Resend account administration, or automatically grant independent external-provider permissions. Existing application operations remain subject to Skylar's send/post, schedule, payment, partner, merge/deploy and credential gates. Mofe's requested assignment is `organizer/event/hack-hours` only; his December event edit stays his.

## Exact owner-controlled production activation path (requires release approval)

1. Skylar separately approves the PR merge/deploy and security-sensitive account/Access provisioning. The production main-push workflow deploys, so **do not merge** merely to test. The owner confirms the named Palmer mailbox/identity, creates or confirms the existing HTV `users` row via **ordinary first sign-in**, and verifies exact email/user ID and current roles. No login code, magic link, credential or session is copied into chat or a CLI.
2. A legitimately signed-in **existing global super-admin** uses the normal `POST /api/admin/roles` route to grant `{"email":"<confirmed Palmer HTV email>","role":"super_admin","scope_type":"global","scope_id":"*","action":"grant"}`. This new API capability is super-admin-only, audited atomically, disallows service self-grants, and is subject to the vault seat cap. Read back `/api/admin/roles`, target, scope, actor/audit and effective vault seats. The service token cannot do this before the Palmer user already has the role. **This is one-time owner provisioning, not a human login per task.** If Skylar chooses only `admin`, the same route grants it but the principal will not have super-admin capabilities; do not call that full highest-role access.
3. Owner creates a **dedicated Cloudflare Access self-hosted application** on an API-only hostname such as `palmer.hackthevalley.org` routed to this HTV Worker, covering the hostname and restricted to one owner-issued Service Auth token (no general Allow policy). Do not put Access in front of the public `hackthevalley.org/api/*` routes. Owner confirms the application AUD and team domain; configures Worker `HTV_SERVICE_ENABLED=1`, `HTV_ACCESS_HOST=palmer.hackthevalley.org`, `HTV_ACCESS_ISSUER=https://<team>.cloudflareaccess.com`, `HTV_ACCESS_AUDIENCE=<dedicated AUD>`, `HTV_ACCESS_CLIENT_ID=<dedicated client ID>` and `HTV_ACCESS_PRINCIPAL_EMAIL=<verified lower-case Palmer email>`. These are owner-controlled deployment settings, **not request parameters**. The client secret remains only in an approved secret manager and is delivered to the operator's environment without source, shell history, stdout, chat or Skyvault. Changes to Access, hostname routing, Worker settings or deploy require explicit owner approval. Default/missing/disabled configuration denies service access.
4. Owner tests `GET /api/admin/me` on the Access hostname via `node scripts/htv-palmer-client.mjs GET /api/admin/me`, then reads `GET /api/admin/roles`, confirming **Palmer's exact user ID and global `super_admin`**; probes a role-gated cross-event read and checks Access/HTV audit logs. On a separately approved Mofe assignment, use `POST /api/admin/roles` with `{"email":"mofmofcool@gmail.com","role":"organizer","scope_type":"event","scope_id":"hack-hours","action":"grant"}` and read back exactly that row and no global Mofe role. Do not perform Mofe's event edit.

### Operator client

`node scripts/htv-palmer-client.mjs GET /api/admin/me` reads through the dedicated Access hostname. For an **already approved** write, pipe an exact JSON object on stdin into `node scripts/htv-palmer-client.mjs POST /api/admin/roles`; never place secrets or JSON credentials in argv. The client reads `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET` from the operator's secret-manager-injected environment, sends them only as Access headers over HTTPS, refuses redirects and non-`/api/` paths, and prints the API response for readback. It does not create users, provision Access, grant roles by itself, or waive action approval. It refuses auth and social-vault routes to avoid printing credentials; use the existing signed-in HTV vault UI with separate approval for any credential operation.

## Rotation, disable and revocation

Owner disables the service immediately by `HTV_SERVICE_ENABLED=0` (or removes the bound client ID), then verifies denial even with an unexpired assertion. Also revoke/delete the token and its Service Auth policy at Cloudflare; provider disable must be verified there, not inferred from a local test. Rotate by creating a new dedicated token, updating the policy and owner-controlled client-ID binding, verifying the new identity and disabling the old token. To remove Palmer's application privileges, an existing super-admin revokes Palmer's global role through the same audited role API and reads back the row/audit/vault seats. Revoke both role and Access token/config; one without the other is incomplete. No production resources are created or modified by this review-only PR.

A local provider-disable simulation is **not** proof that a Cloudflare policy was changed. No live signed-in Palmer, service principal, production grant or deploy was exercised.
